## 1. 产品概述

### 1.1 背景与问题

医学学术会议的会务人员需要在每场演讲之间切换串场画面（演讲者介绍页、环节分隔页），这些画面需要根据会议日程和演讲者资料逐一制作，通常委托设计人员手工排版，存在以下痛点：

- **工作量大**：一场会议往往有数十位演讲者，每人需要一页双语履历；
- **易出错**：姓名、职称、医院、履历等信息手工搬运，错误率高；
- **格式不统一**：不同会议（16:9 屏幕 / 超宽 LED 屏）需要两套排版参数；
- **沟通成本高**：设计人员不懂医学内容，修改迭代慢。

### 1.2 产品定位

**会议串场 PPT 生成器**是一款面向会议会务人员的桌面工具：输入会议日程文件和演讲者资料文件，自动提取结构化信息，按固定模板一键生成中英双语串场 PPT。

### 1.3 核心价值

| 价值点 | 说明 |
|--------|------|
| 自动化 | 日程识别 + 演讲者信息提取 + PPT 排版全流程自动完成，人工只需校对 |
| 准确性 | 结构化提取 + 可编辑表格，人工可在生成前修正任何字段 |
| 双格式 | 一套数据生成 16:9 和超宽 LED 屏两种 PPT，布局参数独立维护 |
| 零设计依赖 | 固定代码排版（python-pptx），不依赖 AI 生成内容，输出稳定可预期 |

## 2. 目标用户与使用场景

### 2.1 目标用户

| 角色 | 描述 |
|------|------|
| 会务人员（主要用户） | 负责会议现场串场画面准备，非设计专业人员 |
| 医学事务专员 | 医药企业市场/医学部，负责学术会议执行 |

### 2.2 典型使用场景

1. 会议前 1-2 天：收集会议日程（图片/表格）和全部演讲者简历（Word/PPT/PDF）
2. 上传日程 → AI 识别 → 在表格中人工校对（改名、补时、改标题）
3. 上传演讲者资料 → AI 提取 → 校对姓名/职称/医院/履历/照片
4. 上传首页和内容页背景模板
5. 选择 16:9 或超宽屏 → 一键生成 PPT
6. 现场播放，如日程临时变动重新生成

## 3. 功能需求

> 优先级：P0 = 必须有（核心流程），P1 = 应有（重要增强），P2 = 可有（体验优化）

### F1 用户系统（P0）

| 编号 | 需求 | 说明 |
|------|------|------|
| F1-1 | 注册 | 用户名 + 密码 + DeepSeek API Key（选填，可在设置中补填） |
| F1-2 | 登录 | 用户名 + 密码认证 |
| F1-3 | 密码安全 | SHA256 + 随机盐哈希存储，不存明文 |
| F1-4 | 账户设置 | 修改密码；配置 DeepSeek API Key 与 OCR.space API Key（按用户存储） |
| F1-5 | 本地数据库 | SQLite 单文件存储用户与演讲者历史数据 |

### F2 演讲者资料管理（P0）

**输入格式**：DOCX / DOC / PPTX / PPT / PDF（可多选上传）

| 编号 | 需求 | 说明 |
|------|------|------|
| F2-1 | 信息提取 | 从每份资料提取：姓名、职称（默认"教授"）、所属医院、履历文本、照片 |
| F2-2 | 照片提取 | 从文档内嵌图片中筛选候选人像（高度 ≥ 3cm），取最大者作为头像 |
| F2-3 | 简历首行过滤 | 资料首行若为"姓名 + 职称"（如"朱颜铂 教授"），不作为履历内容 |
| F2-4 | 医院名解析 | 机构不以"医院"结尾时（简称），调用 AI 查询官方全称并替换 |
| F2-5 | 英文履历 | 演讲者姓名为英文时，自动翻译履历生成英文版（供英文履历页使用） |
| F2-6 | 演讲者列表 | 表格展示姓名/职称/医院/照片/履历预览，支持双击编辑 |
| F2-7 | 手动新增/删除 | "新增"按钮手动录入演讲者；"删除"按钮删除选中条目（含照片文件） |
| F2-8 | 编辑对话框 | 可修改姓名、职称、医院、中文履历、英文履历、照片（上传/清除/预览） |

**兼容性规则**：
- .doc / .ppt 二进制格式通过 OLE 解析提取文字与图片（无需安装 Office）
- DOCX 压缩包 CRC 损坏时通过旁路读取恢复图片
- PPTX 中占位符内的图片、PDF 内嵌 XObject 图片均可提取

### F3 会议日程识别（P0）

**输入格式**：JPG / PNG 图片、XLSX、DOCX / DOC、PPTX / PPT

| 编号 | 需求 | 说明 |
|------|------|------|
| F3-1 | 图片日程识别 | 图片 → OCR 文字识别 → AI 结构化还原（压缩至 200KB 内上传） |
| F3-2 | 文档日程识别 | XLSX/Word/PPT 直接提取文字 → AI 结构化还原（无 OCR 环节） |
| F3-3 | 结构化字段 | 顺序号、时间段、中文标题、英文标题、讲者姓名、主持人、机构、环节类型 |
| F3-4 | 环节类型 | section（章节分隔）/ opening（致辞）/ speech（演讲）/ panel（讨论）/ closing（总结） |
| F3-5 | 姓名规范 | 讲者/主持列只保留纯姓名，自动剔除"教授""主任"等职称 |
| F3-6 | 日程表格编辑 | 识别结果表格化展示，支持单元格双击编辑 |
| F3-7 | CSV 导入/导出 | 日程数据可导出 CSV 人工批量修改后重新导入 |

### F4 模板背景设置（P0）

| 编号 | 需求 | 说明 |
|------|------|------|
| F4-1 | 首页背景 | 上传图片/PPT，用于封面、环节分隔页、结束页背景 |
| F4-2 | 内容页背景 | 上传图片/PPT，用于履历页、开场提醒页背景 |
| F4-3 | PPT 模板提取 | 上传 PPTX/PPT 模板时自动提取每页幻灯片背景图（python-pptx 解析 + OLE 回退） |

### F5 PPT 生成（P0）

| 编号 | 需求 | 说明 |
|------|------|------|
| F5-1 | 尺寸选择 | 16:9（13.3"×7.5"）/ 超宽 LED 屏（7.9"×1.6"，约 5:1），各维护独立布局参数表 |
| F5-2 | 语言模式 | 中英双语 / 纯中文 |
| F5-3 | 固定排版 | python-pptx 固定代码生成，排版稳定，不用 AI 生成内容 |
| F5-4 | 页面结构 | 封面 → 开场提醒×2 → 每个环节（分隔页 → 履历页×N）→ 结束页 |

**分隔页规则**：
- 常规环节：讲者与主持分行显示，带角色标签（"主讲嘉宾：""主持嘉宾：""大会主席："等）
- 开幕致辞 / 会议总结：不区分角色，姓名合并去重，仅显示"姓名 职称"
- 标题超过 22 字时嘉宾行下移一行，避免重叠
- 二字中文姓名中间加空格（"陈晨"→"陈 晨"）；英文姓名前缀 "Prof. " 且不拆散（"Theo M. de Reijke" 视为一人）

**履历页规则**：
- 有照片：左侧头像（人脸检测居中裁剪 + 阴影效果），右侧履历
- 无照片：宽版纯文字履历
- 单行 ≥ 100 字时按"、"或"，"拆分换行（分隔符不保留）
- 履历缺失时显示"姓名（信息缺失）"占位，不中断生成
- 开幕致辞/总结环节同一人只生成一页履历（去重）
- 英文姓名演讲者生成两页：第一页中文，第二页英文（角色标签英文、姓名 "Prof. X"）
- 履历过长时自动缩小字号、调整行距

### F6 操作体验（P1）

| 编号 | 需求 | 说明 |
|------|------|------|
| F6-1 | 进度反馈 | 识别/生成过程显示进度条与状态文字，完成后提示结果 |
| F6-2 | 生成前置校验 | 日程、演讲者、背景模板齐全才允许生成；API Key 缺失时明确提示 |
| F6-3 | 失败容错 | 单个文件识别失败不影响其他文件；网络/API 异常有明确错误提示 |

## 4. 非功能需求

## 5. 关键业务规则汇总

1. **姓名唯一性**：演讲者以姓名为唯一标识，同名后录入覆盖先录入
2. **职称回退**：未匹配到演讲者资料或资料无职称时，界面显示统一回退为"教授"
3. **议程姓名**：讲者/主持列提取时剔除职称词（教授/主任/院长/博士/Prof./Dr. 等），保留纯姓名
4. **多姓名拆分**：中文姓名按分隔符（、，/；）及空格+职称词拆分；英文姓名（含中间名、缩写）整体保留不拆分
5. **医院简称解析**：机构不以"医院"结尾时调用 AI 扩展全称，失败保留原文
6. **英文演讲者**：过场页姓名显示 "Prof. 姓名"；履历页中英双页，英文页角色标签同步英文
7. **AI 输出规范**：temperature=0.1、超时 120s、JSON 输出、结构化校验后入库

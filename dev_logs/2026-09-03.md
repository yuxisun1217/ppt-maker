## Linux 运行兼容性审计（Web 版）

### 结论

Web 版可在 Linux 直接运行，无需任何代码改动。审计项：

- **依赖**：requirements.txt 移除 pywin32 后全部为双平台包
  （python-pptx/Pillow/opencv-python-headless/psycopg2-binary/
  uvicorn[standard] 等均有 Linux wheel，Docker 用 python:3.12-slim）；
- **平台 API**：代码中无 win32/winreg/msvcrt/os.startfile/sys.platform
  等 Windows 专属调用；
- **路径**：无硬编码 Windows 路径/反斜杠；数据目录全部锚定
  `Path(__file__)`（BASE_DIR），与 CWD 无关，SQLite 相对路径也重定位到
  BASE_DIR；临时文件用 tempfile（跨平台）；
- **编码**：所有文件 I/O 为二进制或显式 `encoding='utf-8'`，
  无 GBK/cp936 依赖；日志 handler 显式 UTF-8；
- **SQLite 线程安全**：`check_same_thread=False` 已配置，FastAPI
  线程池/后台任务在 Linux 下行为一致；
- **字体**：PPT 仅写入字体名（Microsoft YaHei）由客户端渲染，
  服务端生成不依赖系统字体；
- **部署**：Dockerfile（slim + 单 worker）、docker-compose（Postgres
  alembic 迁移）、start_dev.sh 均 Linux 兼容；加密密钥兜底落
  `data/encryption.key`（web_data 卷内，跨重建持久）。

### 验证

- 端到端生成冒烟：不走 AI，用编辑数据（AgendaItem/Speaker）直接调
  `generate_ppt_async` → 9 页 PPTX（36KB）生成成功。
- 唯一注意项：容器内为 UTC 时区，任务时间戳为 UTC（仅展示层面）。

## 演讲者照片支持手动重新裁剪

### 需求

解析结果中如对某位演讲者的照片裁剪不满意，支持重新裁剪。

### 方案

自动检测是确定性的，重跑结果不变，因此重新裁剪以**用户手动框选人脸**
为主：在照片灯箱内拖拽框选人脸区域 → 服务端按同一套上半身构图公式
（脸为中心、上留发、下至胸肩、脸约占画面 1/3）重新裁剪 → 生成新照片。

### 修改

- `extractors/speaker_extractor.py`：抽取 `_upper_body_box`（上半身裁剪框
  计算）与 `crop_portrait_with_face`（按给定人脸框裁剪，可指定输出路径），
  `_crop_head_portrait` 自动路径改为复用二者，行为不变；
- `main_web.py`：新增 `POST /api/photo/re-crop`。入参 `file_id`（源图：
  原图或当前照片）+ 可选 `face_box`（归一化 0~1 坐标；缺省重新自动检测）。
  校验文件归属（同 /api/upload/{id}：未知 404 / 越权 403）、框参数
  （数值、范围、最小尺寸）；裁剪结果落盘为新 upload，原图不动；
  返回 `{file_id, filename, preview}`；
- `web/web_prototype.html`：照片灯箱新增「重新裁剪」按钮 → 进入框选模式
  （拖拽显示选区、松开提交、Esc/取消退出），成功后更新卡片缩略图与
  灯箱显示，并保留 original_file_id 供反复重裁。无原图时（手动上传的
  未裁剪照片）以当前照片为裁剪源，裁剪后将其登记为 original。

### 验证

- TestClient 全链路（临时 SQLite）：注册/登录 200；上传 409KB 测试照片；
  手动框裁剪 200（新 upload 208KB、preview 为 dataURL）；框太小 400；
  自动检测路径 200；跨用户 403；未知文件 404；
- 重构后 `_crop_head_portrait` 原自动裁剪在测试照片上仍正常（检出唯一人脸并裁剪）；
- 前端内联脚本 `node --check` 全部通过。

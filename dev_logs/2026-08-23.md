# 2026-08-23 开发日志

## Web 后端核心逻辑迁移

将桌面端核心逻辑接入 Web 后端，桌面端功能保持不变。

### 改动内容

1. **`extractors/file_input.py`（新增）** — 共享输入适配：extractors 同时接受
   `bytes`（Web 上传）和本地路径（桌面端），bytes 物化为临时文件供内部逻辑使用
2. **`extractors/agenda_extractor.py`** — `extract_agenda(data, api_key, ocr_api_key, filename=None)`
   新增 bytes + filename 输入，路径调用兼容不变；增加 logger
3. **`extractors/speaker_extractor.py`** — `extract_speaker(data, api_key, filename=None)`
   同上；`filename` 用于扩展名识别和姓名推断
4. **`tasks.py`（新增）** — Web 任务层：
   - 任务注册表（内存 dict，TODO 换 DB）+ 进度上报（pending/running/done/failed）
   - `run_generation_task()` 完整管线：读上传 → 提取日程 → 提取演讲者 → generate_ppt
   - `generate_ppt_async()` — 用 asyncio.to_thread 封装同步核心函数（满足异步任务要求）
   - 选型说明：用 FastAPI BackgroundTasks 而非 Celery（单用户本地工具，无 broker 基础设施；
     同步后台函数跑在 Starlette 线程池，事件循环不阻塞）
5. **`main_web.py`** — 接入真实管线：
   - GenerateRequest 改为 agenda_file_id + speaker_file_ids + api_key/ocr_api_key
     + 可选背景图 + slide_size/lang（TODO: Key 改为服务端按账号读取，目前前端传参）
   - 上传清单持久化到 `data/web_uploads/manifest.json`（服务器重启后上传记录不丢失）
   - 日志：控制台 + `logs/web_backend.log`（RotatingFileHandler，2MB×3），
     请求中间件记录每个请求，任务层带 task_id 前缀记录全流程
   - 敏感字段（api_key/ocr_api_key）不写入任务记录（/api/status 会返回任务记录）

### 验证

- extractors 新旧两种调用签名 bind 测试通过（桌面端位置参数、Web 端 bytes+filename）
- 无 Key 请求 → 任务优雅失败（status=failed，含完整 traceback，日志落盘）
- 上传清单重启恢复已修复（首次 E2E 因服务器重启丢失 UPLOADS 注册表失败）
- **真实端到端通过**：会议日程.jpeg + Notes.DOCX + 双背景图 → 54 页 16:9 PPT
  （日程提取 35s、演讲者提取 53s、总耗时约 2.5 分钟，输出 2.4MB 含照片）

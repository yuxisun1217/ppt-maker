# 2026-08-28 开发日志

## 演讲者照片提取：全身照裁剪为头部特写

### 需求

用户要求：演讲者图片提取时，如果是全身照，仅裁剪保留大头像。
附加约束：图片可以裁剪，但**绝对不能扩图**（不得超出原图范围、不得放大）。

### 第一版（DeepSeek Vision 定位）——被真实 Key 实测推翻

- 用 `utils.deepseek_client.extract_from_image`（model=deepseek-v4-pro）判断
  是否全身照并返回头部区域，失败时对高宽比 ≥ 2.2 的竖图启发式裁剪顶部。
- 用户实测王磊苹简历（全身照 1650×2475，高宽比仅 1.5）未裁剪。日志显示
  `DeepSeek API 错误 (400): This model does not support image`——
  **DeepSeek V4 API 不支持 image_url 输入**（与 dev_logs/2026-05-28 结论一致，
  日程图片因此走 OCR.space）。且高宽比 1.5 的全身照（人物填满画幅）低于
  2.2 启发式阈值，两条路径都失效。

### 第二版（最终）：OpenCV Haar 人脸检测（固定代码，无 AI 调用）

`extractors/speaker_extractor.py` 重写 `_crop_head_portrait(photo_path)`：
- `cv2.imdecode` 读图（避免 Windows 中文路径问题）；Haar frontalface 级联
  两轮检测（先严格后宽松）
- 检测不到人脸 → 不裁剪（保留原图）
- 人脸高度 ≥ 画面高度 40% → 已是特写/证件照，不裁剪
- 否则围绕**面积最大**的人脸裁头部区域：上留 0.4×人脸高（头发）、
  下到 1.35×（脖颈）、两侧各 0.85×人脸宽（耳发）；**裁剪框一律 clamp 在
  原图范围内，只裁剪绝不扩图，按原始分辨率保存不放大**
- JPEG 以 quality=95 保存减少重编码损失；PNG 等无损
- 失败一律保留原图并记 warning，不影响提取流程；桌面端与 Web 端共用生效
- 新增依赖 `opencv-python-headless>=4.8`（requirements.txt；用户环境已装 4.13）

### 验证（真实文件 王磊苹-202401-简历.pptx 中的全身照 1650×2475）

- 人脸检测命中 1 张脸：框 (562,383,564,564)，占画面高度 22.8%（顶部 15.5% 起）
- 裁剪框 (364,157,1323,1144) → 959×987 近似方形大头像，完全在原图范围内
- 人脸中心落在裁剪结果 (50.1%, 51.5%) —— 居中
- 像素级验证：裁剪结果与原始区域仅 JPEG 重编码级差异（均值 2.11/255），
  无缩放无填充；结果尺寸 < 原图
- 已是大头像/检测不到脸/读取失败 → 均保留原图（单元测试）
- `py_compile` 通过

### 遗留问题

- Haar 对侧脸/低头/帽子遮挡可能检测失败 → 保留原图，可用前端「更换照片」手动处理
- 多人合照取面积最大人脸（通常为本人），极端情况可能裁错人；检测失败不裁剪
- 真实效果待用户侧实测（重启 8000 后端后重新解析）

## 解析结果：点击头像查看完整照片

### 需求

演讲者解析结果中点击头像可查看完整照片（裁剪前的原图）。

### 后端

- `extractors/speaker_extractor.py`：`Speaker` 新增 `photo_original_path` 字段。
  `_crop_head_portrait` 实际裁剪成功时，把裁剪前原图另存为
  `{safe_name}_完整照片{ext}`（同会话照片目录）；未裁剪时留空
- `main_web.py` `/api/parse`：照片持久化重构为 `_persist_photo(src, label)` 闭包；
  `photo` dict 新增 `original_file_id` / `original_filename`（裁剪过才非空，
  文件名为「{姓名}_完整照片.ext」），完整照片同样落盘 web_uploads 并登记 uploads 表
- `database/db.py`：`get_upload` 返回 `user_id`
- 新增 `GET /api/upload/{file_id}`：会话登录后下载上传文件（完整照片原图），
  **归属校验** `user_id != 当前用户` → 403；未知 id / 文件不存在 → 404

### 前端 `web/web_prototype.html`

- 头像缩略图包 `data-photo-view` 按钮 + 放大镜角标 + `cursor-zoom-in`
- 点击弹出灯箱（Esc / 点击关闭）：**默认显示解析结果中的照片（裁剪后大头像）**；
  若有 `original_file_id`，灯箱内提供「查看完整照片」按钮，点击经
  `/api/upload/{file_id}` 拉取完整原图，可再切回（「查看裁剪照片」），
  不自动替换

### 修正（用户反馈：裁剪「不生效」）

- 现象：用户报告赵明川简历照片未裁剪。查 `logs/web_backend.log`：
  `照片已裁剪为头像: 843x1265 → (232,108,559,444)` —— 服务端裁剪实际成功，
  解析结果缩略图也是裁剪后的
- 原因：上一版灯箱会**自动加载并替换为完整原图**，用户点头像看到的是
  全身原图，误以为裁剪未生效
- 修复：灯箱默认显示裁剪后照片，完整原图改为按钮手动切换；卡片角标
  title 统一为「查看照片」

### 验证

- 进程内 parse_materials 测试（monkeypatch 提取器）：11/11 通过，含
  `original_file_id`/完整照片落盘/未裁剪时为空
- 8010 端口端点冒烟：8/8 通过（未登录 401、本人 200 字节一致、
  他人 403、未知 id 404）；测试账户与数据已清理
- `py_compile` + 前端 `node --check` + HTML 标签配平通过

### 使用说明

- 重启 8000 端口后端 + 浏览器 Ctrl+F5 后，**重新解析**资料即可生效
  （旧解析结果无完整照片字段）

## 生成 PPT：全身照显示裁剪为上半身头像

### 需求

用户要求：`ppt_generator.py` 介绍页排版时，演讲者全身照做显示裁剪
（srcRect），只显示上半身头像——不再显示几乎整张全身照。

### 背景

- 提取阶段 `_crop_head_portrait` 已把全身照物理裁剪为头像，但人脸检测
  失败的照片（侧脸/遮挡）会以全身照原样进入生成阶段
- 原 `_make_bio` 显示裁剪只做 0.68 比例适配：竖图保留全宽裁高，人脸居中
  在可见区 40% 处。全身照 1650×2475 时可见区几乎覆盖整图（下边仅裁 2%），
  人物全身入镜

### 修改

`ppt_generator.py` `_make_bio`：

- 人脸检测结果新增 `face_found` 标记（原默认中心点逻辑保留）
- 可见区计算新增第一分支：**人脸检出且人脸高度 < 画面高度 40%（全身照）**
  - 可见高度 = 2.5×人脸高（上留 0.5×人脸高做头发、下至胸肩），
    宽度按 0.68 推导；人脸约占可见高度 40%、脸顶在可见区 20% 处
  - 推导宽度超过原图宽度时退化为「保留全宽裁高」——只裁剪绝不扩图
  - 可见区一律 clamp 在原图范围内（与提取阶段同一原则）
- 已裁头像（人脸 ≥ 40%）与未检出人脸的照片走原比例适配分支，行为不变
- 裁剪仍是 pptx `srcRect` 显示裁剪，不修改照片文件

### 验证

- `py_compile` 通过
- 可见区数学验证（独立脚本复算分支逻辑）：
  - 王磊苹全身照 1650×2475、脸 (562,383,564,564) → 可见区
    (365,101)-(1323,1511)，人脸占可见高 40%、宽高比 0.68；旧逻辑为全图
  - 窄竖图推导宽度超原图 → 退化全宽分支，可见区不出界
  - 已裁头像 / 未检出人脸 / 脸贴顶 → 均不出界，比例保持 0.68 无变形
- 真实效果待用户侧实测（重新生成 PPT 生效）

## 修正（用户反馈：照片里脸太大）：裁剪放宽为上半身

### 现象

- 提取阶段裁剪成紧大头像：王磊苹照片 959×987，脸占照片高度 **57%**；
  生成阶段显示裁剪可见高度 2.5×脸高，脸占可见高度 **40%**
- PPT 里脸过大，且看不到上半身（肩/胸）

### 修改

1. `extractors/speaker_extractor.py` `_crop_head_portrait`：紧头部特写 → 上半身像
   - 高：上 0.6×脸高（头发）→ 下 2.4×脸高（胸肩），总高 3.0×脸高，
     脸约占 **1/3**
   - 宽：两侧各 1.2×脸宽（≈1.4×头宽，含肩）
   - 阈值不变（人脸 ≥ 40% 不裁剪）；裁剪框仍 clamp 在原图内，只裁剪不扩图
   - 日志文案「头像」→「上半身」
2. `ppt_generator.py` `_make_bio`：全身照显示裁剪可见高度 2.5× → 4.5×脸高
   （脸约占可见高度 **22%**，脸顶在可见区 27% 处）；区域放不下（宽或高超图）
   时退回原比例适配分支，保证可见区不出界

### 验证

- `py_compile` 通过
- 王磊苹真实数据复算：提取裁剪框 (167,44)-(1520,1736) = 1353×1692，
  脸占高 33%（原 57%）；生成显示裁剪 5 个用例（全身照/已裁半身像/
  高瘦全身照/未检出人脸/脸贴顶）均不出界、比例 0.68、脸占可见高 22%~33%
- 几何约束：照片自身比例 ≈ 0.68 的全身照（如王磊苹 1650×2475），
  0.68 显示框内放不下 4.5×脸高区域，自动退回显示近全图（脸 23%），无法更紧
- 待用户侧实测（需重新解析资料 + 重新生成 PPT）

## 修正：`_make_bio` 全身照分支 `fy` 未定义 → 照片不渲染

### 现象与原因

- 进程内验证时发现：人脸检出且人脸高 < 40% 的全身照走 `upper_ok` 分支，
  `anchor_y = fy - 1.2 * fh` 中的 `fy` 从未定义（人脸检测返回的是 `y`），
  抛 NameError 被外层 `except: pass` 吞掉 → **照片完全不添加到页面**
  （本次对齐验证时用陈占红全身照复现：页面只有背景图，无演讲者照片）
- 该分支自「脸太大修正」引入（独立脚本验证只复算了数学，未走真实代码路径）
- 影响范围：提取阶段未裁剪（人脸检测失败/已裁照片中人脸 < 40%）的照片
  在生成时静默丢失

### 修复

- `fy - 1.2 * fh` → `y - 1.2 * fh`（人脸框左上角 y 即 `detectMultiScale` 返回的 `y`）

### 验证

- 修复后用真实照片进程内生成：全身照（陈占红）→ 照片出现且带
  `srcRect l=16037 r=1768 b=6727` 上半身显示裁剪；已裁上半身像（王磊苹）→
  照片出现带合理 srcRect；两种照片 `off=(0.80, 1.50)` 与履历上沿对齐
- `py_compile` 通过
- 需重启 8000 后端后重新生成生效

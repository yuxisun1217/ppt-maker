# 2026-09-01 开发日志

## 照片裁剪误伤修复：王碧芸人脸被裁掉、丛斌斌合照裁错人

### 问题

最新 web 生成记录（task 99f34095…，2026-08-31 15:41）中两位演讲者照片裁剪错误：

- **王碧芸**（原图 571×1016）：裁剪结果 506×697 完全不含人脸——
  真实人脸在 (211,186)（frontal+alt2+profile 三个级联都确认），
  位于裁剪线 y=319 之上；被选中的"人脸"(252,479) 是衣服纹理误检，
  只有 frontal 一个级联报出，且面积更大压过了真脸。
- **丛斌斌**（原图 1648×2472 + 519×519）：原图是多人合照
  （检测到 10+ 人脸框），旧逻辑"取面积最大的人脸"任意裁出画面下方某个人。

### 根因

`_crop_head_portrait` 只用单个 Haar 级联（frontal）、取面积最大的框：
单级联误检（王碧芸）和多人合照（丛斌斌）都会裁错。
`ppt_generator._make_bio` 的 srcRect 智能居中同样用单级联检测（minNeighbors=3），
存在同样的误检风险。

### 修改

**`extractors/speaker_extractor.py` 新增 `detect_face_strict(img_bgr)`**：

- frontal + alt2 两个级联都必须在同一区域（重叠 ≥ 50%）以高置信度
  （minNeighbors ≥ 5）检出人脸，才算"确认人脸"；两轮扫描（严格/宽松）
  的结果按簇合并，每级联取最高 mn
- 人脸中心还须位于画面高度 68% 之上（排除合照中画面下方的人物）
- 确认到 0 个或 ≥ 2 个（合照）返回 None——宁可保留原图也不裁错

**`_crop_head_portrait`（解析端裁剪）**：改用 `detect_face_strict`，
仅在唯一确认人脸时裁剪；裁剪框仍一律 clamp 在原图内（只裁剪绝不扩图）。

**`ppt_generator._make_bio`（生成端 srcRect 智能居中）**：
改用同一 `detect_face_strict`，检测不到时退回原有居中/比例裁剪逻辑。

### 验证

- 王碧芸原图 → 确认唯一人脸 (210,186,189,189) → 裁剪出 454×567
  含脸上半身 ✓；丛斌斌合照 → None → 保留原图 ✓
- 回归：对 web_uploads 中全部历史上传 pptx（100+ 张照片）跑新检测，
  除上述两处修复外，其余照片均与旧逻辑选出同一人脸，或正确识别为
  "已是特写"跳过裁剪（保守，无害）
- 端到端冒烟：王碧芸 bio 页 srcRect 按人脸水平居中（脸完整在框内）；
  丛斌斌 bio 页仅 2% 比例微裁，整张合照可见，不切人脸
- `py_compile` 通过

### 遗留说明

- 已生成的记录不会自动变好：用户需重新「资料解析」+ 生成，
  照片会按新逻辑重新裁剪。
- 丛斌斌的源文件本身就是合照，程序无法可靠判断照片中哪一位是本人——
  重新解析后将保留整张合照，建议用户在网页上「更换照片」上传单人证件照。

## 过场页单人演讲者：介绍行左边沿右移 5 汉字

### 需求

过场页（divider）演讲者只有一人时，嘉宾介绍文本框左边沿向右移动
约 5 个汉字长度（右边沿不动，盒子变窄）。

### 修改（`ppt_generator.py`）

- `_make_divider()` 新增 `single_person` 参数：单人时在原有
  `left = 0.5" + 2 字符` 基础上再 `+= 5 * speaker_sz`
  （1 汉字宽 ≈ 1 个字号，对 16:9/超宽屏参数表均适用）；
  右边沿保持 `w - 1" - 2 字符` 不变。
- `generate_ppt()` 计算过场页人数并传入：
  - opening/closing：合并去重后的 `len(parts)`
  - 其他：`len(_split_names(speaker_name)) + len(_split_names(host))`
  - `== 1` 时 `single_person=True`（主持+主讲同一个人时经过去重也为单人）

### 验证

冒烟测试（16:9）：

- speech 单人 → left = 3.611"（0.5" + 2 字 + 5 字）✓
- speech 双人（主讲+主持）→ left = 1.389"（不移动）✓
- opening 单人 → left = 3.611" ✓
- 文本框 align=l、右沿不变；`py_compile` 通过

注：验证脚本曾因 `_spread_name` 在 2 字姓名中插入 U+00A0 而匹配不到
"王五" 连续子串，属测试脚本问题，非代码问题。

## 过场页嘉宾介绍行改为居中（同日调整，替代上一条单人偏移）

### 需求

过场页演讲者姓名行由左对齐改为居中。

### 修改（`ppt_generator.py`）

- `_make_divider()`：介绍行 `align` 改回 `PP_ALIGN.CENTER`；
  文本框改为相对页面中线对称——`left = 0.5" + 2 字符`，
  `width = w - 2 × left`（左右各内缩 0.5"+2 字符），
  文本视觉中心与幻灯片中线完全重合。
- 移除上一轮新增的 `single_person` 参数及人数计算：单人左边沿右移
  5 汉字是为左对齐服务的，居中时保留不对称盒子会使文字偏向页面右侧，
  故一并撤销（如需恢复可重新加回）。

### 验证

冒烟测试（16:9，speech 单人/双人 + opening 单人共 3 个介绍行文本框）：

- left = 1.389"、width = 10.555"（左右对称）
- 盒子中心 = 6.6665" = 页面中线（误差 < 1 EMU）
- `algn="ctr"` ✓；`py_compile` 通过

## 共享 API Key：全员共享使用、仅管理员可见可改、密文落库

### 需求

DeepSeek / OCR.space Key 作为公用变量：所有用户共享使用；只有管理员
可见并可修改；数据库中加密保存。

### 实现

- **`utils/crypto.py`（新增）**：Fernet 对称加密。密钥优先取环境变量
  `ENCRYPTION_KEY`；未配置时自动生成并持久化到 `data/encryption.key`
  （不入库，Docker 中随 web_data 卷持久化）。解密失败返回空串兜底。
- **`database/models.py`**：新增 `SystemSetting`（key-value 表）。
- **`database/db.py`**：`get_shared_keys()`（解密读取）/
  `set_shared_keys()`（加密落库；None=不动，空串=清空）。
- **`alembic/versions/0003_system_settings.py`**：PG 迁移；SQLite 由
  `init_db()` 的 create_all 自动建表。
- **`main_web.py`**：
  - `GET/PUT /api/settings/shared-keys`（仅 `require_admin`），
    GET 返回解密明文（仅管理员可见），PUT 加密落库；
  - `/api/parse`、`/api/generate` Key 解析优先级统一为
    **账号个人 Key > 请求携带 > 共享 Key**；
  - `tasks.create_task` 原有脱敏逻辑确保任务记录不落任何明文 Key
    （`_SECRET_FIELDS` 剔除）。
- **`tasks.py`**：缺 Key 报错文案提示可配置个人/共享 Key。
- **前端**：
  - `web/admin.html` 顶部新增「共享 API Key」卡片：加载/保存/显示切换/
    已配置状态徽章，仅管理员页面可见；
  - `web/settings.html` 提示文案更新：个人 Key 留空时自动使用共享 Key。
- **依赖**：`requirements.txt` 新增 `cryptography>=42.0`。
- **配置/文档**：env.example 增加 `ENCRYPTION_KEY` 说明（含生成命令）；
  README 增加功能特性、环境变量表、API 摘要与注意事项说明。

### 验证

- 管理员写入/读取共享 Key → 解密明文一致 ✓

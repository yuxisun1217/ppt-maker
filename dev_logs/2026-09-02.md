### 需求

普通用户在页面上隐藏「账户设置」按钮（后端 `/api/account/keys` 等接口
保留）；管理员保留该按钮。

### 修改（`web/web_prototype.html`）

- 顶部导航 `#btn-account`（账户设置）默认加 `hidden`；`loadMe()` 中
  `u.is_admin` 时与「用户管理」链接一起显示（与 `#link-admin` 同一模式）。
- 按角色区分无个人 Key 时的登录提示：
  - 管理员：可到「账户设置」填写；
  - 普通用户：提示将使用管理员配置的共享 Key（如已配置）。
- **连带放宽三处前端 Key 硬拦截**（否则普通用户没有个人 Key 会被挡在
  前端，上一轮「共享 Key」功能对目标用户完全不可用）：
  - `parseFiles()`、`startGenerate()`、`commonGuard()` 移除
    "无本机 Key 且账号未配置 Key 即拦截"的判断，改由服务端解析
    （个人 Key > 本机 Key > 共享 Key），缺少时由服务端返回友好报错；
  - 恢复 `apiKey` 局部变量声明（请求体仍携带本机 Key）。
- 后端连通性错误提示去掉「到账户设置修改后端地址」表述
  （普通用户已看不到该按钮）。

### 验证

- 提取页面内联 JS 用 `node --check` 语法检查通过。
- 后端接口未改动（`/api/account/keys`、`/api/settings/shared-keys` 原样）。
- 说明：settings.html 仍可通过直接 URL 访问（后端接口保留，
  与需求一致）；普通用户保存个人 Key 的接口调用仍可正常工作。

## 共享 Key 缺失警告 + 两项必填

### 需求

所有用户登录后都检查共享 DeepSeek / OCR.space Key 是否存在；任一缺失
弹出红/橙色警告，提示联系管理员添加；两项共享 Key 均为必填。

### 修改

- **`main_web.py`**：
  - 新增 `GET /api/settings/shared-keys-status`（任意登录用户）：
    只返回 `deepseek_configured` / `ocr_configured` 布尔值，
    不暴露 Key 值本身（Key 明文仍仅管理员可见）；
  - `PUT /api/settings/shared-keys` 增加必填校验：按「None=保持、
    空串=清空」语义先算出最终状态，任一为空 → 400
    「共享 DeepSeek API Key 与 OCR.space Key 均为必填，不能留空」
    （校验在落库前，不会提交半空状态）。
- **`web/web_prototype.html`**：
  - 页头下方新增橙色警告条 `#shared-key-warning`（sticky，默认隐藏）；
  - `loadMe()` 成功后调用 `checkSharedKeys(u)`：请求 status 接口，
    任一缺失时显示「⚠ 共享 DeepSeek API Key 与 OCR.space Key 未配置，
    请联系管理员添加后使用」；管理员显示「请前往「用户管理」页配置」
    链接；全部配置时隐藏。
- **`web/admin.html`**：共享 Key 卡片状态徽章未配置时改橙色
  「未配置（必填）」；输入框占位符改「必填」；提示文案更新
  （两项必填、未配置时所有用户登录会收到警告）。

### 验证

TestClient（临时 SQLite，产物已清理）：

- 未登录访问 status → 401 ✓
- 普通用户 status → 200，初始 `{false, false}` ✓
- PUT 空值 / 只填一项 → 400（必填提示）✓
- 完整填写 → 200，status 翻转为 `{true, true}` ✓
- 部分更新（None 保持另一项）→ 200 且状态完整 ✓
- 前端两页内联 JS `node --check` 通过 ✓
